All structured provider requests pass through the same gateway cache, with schema validation, timeouts, per-provider request spacing, request deduplication, persistent last-good snapshots, and bounded backoff with jitter. Browser network-offline state, partial source availability, and archive/model data kind are separate concepts. The 24-hour hardware trial must validate those distinctions on the installation's real network.

Raspberry Pi frame rate, thermals, and encoding are unverified until run on the actual Pi. OBS/hardware commissioning is a separate acceptance stage, not established by the software-WebGL soak.

Provider quota reference: https://ll.thespacedevs.com/docs . Multiple validation gateways shared the workstation outbound IP and may have contributed to the observed throttling; this is an inference, not proven attribution. Do not substitute the provider’s stale development endpoint and label it live. Retry-After handling and a quota budget across deployments are reliability follow-up items before adding stations.

## Recorded audit outcomes

The isolated CI audit collected 122 gateway snapshots spanning startup, the two-hour browser run and final checks (22:24:53 UTC through 00:26:05 UTC). No audit request errors occurred. Counts below describe cached envelope status at those sample times; they are neither provider request counts nor provider uptime percentages. Initial unavailable states cleared when the first request completed; occasional TTL-boundary stale states had no provider failure reason.

| Source envelope | Current samples | Stale samples | Unavailable samples | Observed outcome |
| --- | ---: | ---: | ---: | --- |
| ISS estimate | 121 | 1 | 0 | Repeated new source timestamps and retrievals; 45-second precision expiry separately passed the real 62-second offline probe |
| ISS track | 119 | 2 | 1 | Initial fill and bounded TTL refresh; no provider failure reason in this audit |
| EPIC | 122 | 0 | 0 | Re-retrieved successfully; acquisition remained November 1, distinct from new receipt dates |
| Launch Library launches | 121 | 1 | 0 | Repeated schedule refreshes; no 429 in this isolated CI run |
| Launch Library events | 120 | 1 | 1 | Initial fill and repeated schedule refreshes; no provider failure reason |
| NASA Mars archive | 122 | 0 | 0 | July 21, 2021 metadata remained archival; daily refresh was not yet due |
| StarKid reference calendar | 122 | 0 | 0 | Local approximate calendar remained available; deployed override still unconfigured |

The workstation audit separately observed **9 stale launch samples with HTTP 429 among 39 snapshots**, retaining useful last-good schedule data; that audit contains the host-sleep gap and is not an uninterrupted availability measure. The provider limitation is real even though the separate CI egress did not encounter it. Independent Docker offline startup preserved the six warmed remote envelopes as stale and left the local calendar usable. Source timestamps, retrieval dates, fallback behavior and limitations in the table above remain part of acceptance.
